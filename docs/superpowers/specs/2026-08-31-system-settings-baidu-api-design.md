# 系统设置与百度地图 API 配置设计

## 1. 背景与目标

神州车型雷达当前将运行参数放在环境变量中，没有供非技术用户管理第三方 API 的页面。后续地点搜索、消息推送等能力都会引入外部服务，因此本次新增可扩展的“系统设置”子系统，并先完整支持百度地图 API。

本次目标：

- 新增独立系统设置页面和主导航入口。
- 在本机 PostgreSQL 中保存第三方 API 配置，不把真实密钥写入代码、示例环境文件或 Git。
- 完整支持百度地图服务端 AK 的保存、替换、清除、启用和停用。
- 支持真实测试地点输入提示与坐标转换，分别显示测试结果和中文错误。
- 设计可扩展到其他第三方 API，但不提前实现无关服务。

## 2. 范围

### 2.1 本次包含

- 通用第三方集成配置数据模型。
- 百度地图配置的读取、更新、清除和测试 API。
- 百度地图地点输入提示客户端。
- 百度 BD-09 到 GCJ-02 坐标转换客户端。
- 系统设置页面、配置表单、密钥遮罩和测试结果展示。
- 数据库迁移、自动化测试、Docker 迁移与真实 API 验收。
- 部署后将用户提供的 AK 仅写入本机数据库并执行验证。

### 2.2 本次不包含

- 首页地点输入框接入百度地点搜索。该能力将在设置与客户端稳定后单独实现。
- 百度地图可视化、路线规划、天气、路况、公交线路或轨迹服务。
- 用户登录和权限控制。系统仍按个人局域网、无鉴权方式运行。
- 将密钥同步到 GitHub、日志、扫描历史或原始响应表。

## 3. 方案选择

采用“数据库保存配置、代码注册服务能力”的方案。

- 数据库存储启用状态、非敏感配置和密钥。
- 代码定义每个提供商支持哪些字段、如何校验和如何测试。
- 页面只呈现代码已注册的提供商，不允许用户任意填写 URL 或执行任意外部请求。

没有采用纯 `.env` 方案，因为它无法从页面修改；没有采用任意键值表直接驱动网络请求，因为这会扩大误配置和服务器端请求伪造风险。

系统仅供个人局域网使用且用户明确不需要鉴权，本次密钥在本机 PostgreSQL 中保存为明文。API 永远不回传完整密钥，数据库和备份文件仍应视为敏感数据。若未来改为多人或公网部署，再增加主密钥加密与权限控制。

## 4. 数据模型

新增 `integration_settings` 表：

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `id` | integer | 主键 | 内部 ID |
| `provider` | varchar(64) | 唯一、非空 | 提供商标识，本次为 `baidu_maps` |
| `enabled` | boolean | 非空、默认 false | 是否允许业务使用该集成 |
| `config_json` | JSONB | 非空、默认 `{}` | 非敏感配置 |
| `secret_value` | text | 可空 | 服务端 AK |
| `updated_at` | timestamptz | 非空 | 最近更新时间 |

百度地图 `config_json` 当前结构：

```json
{
  "default_region": "广州",
  "test_keyword": "三溪地铁站"
}
```

使用迁移 `0007_add_integration_settings` 创建表。迁移不写入用户 AK。

## 5. API 设计

### 5.1 获取集成配置

`GET /api/settings/integrations`

响应仅返回受支持的提供商和安全状态：

```json
{
  "items": [
    {
      "provider": "baidu_maps",
      "display_name": "百度地图",
      "enabled": true,
      "configured": true,
      "masked_secret": "fSdd****Eysl",
      "default_region": "广州",
      "test_keyword": "三溪地铁站",
      "updated_at": "2026-08-31T16:00:00+08:00"
    }
  ]
}
```

无论任何情况都不返回 `secret_value`。

### 5.2 保存百度地图配置

`PUT /api/settings/integrations/baidu_maps`

请求：

```json
{
  "enabled": true,
  "ak": "可选；为空时保留原密钥",
  "default_region": "广州",
  "test_keyword": "三溪地铁站"
}
```

规则：

- `ak` 缺省、`null` 或空白时保留原密钥。
- 新配置没有密钥且尝试启用时返回 422。
- 地区和关键词去除首尾空白，长度限制为 1 至 64。
- 更新成功后返回与读取接口相同的遮罩结构。
- 唯一提供商来自固定路由，不接受任意提供商名称。

### 5.3 清除百度地图密钥

`DELETE /api/settings/integrations/baidu_maps/secret`

清除密钥并自动将该集成设为停用。返回 204。该操作不删除默认地区和测试关键词。

### 5.4 测试百度地图 API

`POST /api/settings/integrations/baidu_maps/test`

测试使用已保存的地区与关键词，不接受任意外部 URL。执行两个步骤：

1. 调用百度地点输入提示，至少取得一个包含名称和坐标的 POI。
2. 使用第一个 POI 的 BD-09 坐标调用百度坐标转换，转换为 GCJ-02。

成功响应：

```json
{
  "ok": true,
  "elapsed_ms": 168,
  "place_suggestion": {
    "ok": true,
    "name": "三溪地铁站",
    "address": "广东省广州市天河区",
    "bd09_latitude": 23.109,
    "bd09_longitude": 113.422
  },
  "coordinate_conversion": {
    "ok": true,
    "gcj02_latitude": 23.103,
    "gcj02_longitude": 113.416
  }
}
```

错误响应使用 422（未配置或已停用）或 502（百度返回业务错误、格式错误、超时或网络异常），`detail` 为适合页面展示的中文消息，不包含 AK、完整请求 URL 或响应追踪标识。

## 6. 百度地图客户端

新增独立 `BaiduMapsClient`，只负责百度接口适配：

- 基础地址固定为 `https://api.map.baidu.com`。
- 地点提示路径固定为 `/place/v3/suggestion`。
- 坐标转换路径固定为 `/geoconv/v2/`，使用 `model=5` 将 BD-09 转为高德/腾讯坐标，即 GCJ-02。
- 单次请求超时 10 秒。
- 对传输错误、超时、非 2xx、百度非成功状态和缺失字段分别转换为领域错误。
- 客户端通过依赖注入支持测试传输层，不在测试中访问真实百度服务。
- 任何异常文本都不得包含 AK。

## 7. 页面设计

新增 `/settings` 页面，并在主导航加入“设置”。页面保持现有非技术化界面风格。

百度地图配置卡包含：

- 当前状态：未配置、已配置但停用、已启用。
- AK 密码输入框，编辑时不预填真实值。
- 已保存密钥遮罩。
- 默认城市输入框，默认“广州”。
- 测试关键词输入框，默认“三溪地铁站”。
- “保存配置”“测试连接”“清除密钥”三个操作。

保存和测试期间按钮进入禁用/加载状态。测试结果在页面内分两步显示地点检索、坐标转换、示例地点、坐标和总耗时；错误使用现有 toast 并在结果区保留中文说明。

页面明确提示：AK 仅保存在本机数据库，不会显示完整值；系统无鉴权，仅应在可信局域网中开放。

## 8. 数据流

```text
设置页面
  → PUT 配置 API
  → 校验并保存 integration_settings
  → 返回掩码状态

设置页面
  → POST 测试 API
  → 读取已启用的本机配置
  → 百度地点输入提示
  → 百度坐标转换
  → 返回脱敏测试摘要
```

## 9. 安全与日志

- 完整 AK 只出现在请求体内存和本机数据库列中。
- GET、PUT 和测试响应只返回掩码，不返回 AK。
- 应用日志不记录请求体、AK、完整百度请求 URL或百度原始响应。
- Git 中只增加 `BAIDU_MAP_AK=` 的说明时也不得写入真实值；本次页面配置不要求该环境变量，因此默认不增加。
- Docker 数据卷和数据库备份包含密钥，README 必须提示妥善保存。
- 系统无鉴权，设置页只能部署在可信局域网，端口不得直接暴露到公网。

## 10. 测试与验收

自动化测试覆盖：

- 新表迁移和唯一提供商约束。
- 未配置时的安全响应。
- 保存、替换、空值保留、清除和启停规则。
- 所有读取响应均不包含完整 AK。
- 未配置或停用时拒绝测试。
- 地点提示成功、无结果、百度业务错误、HTTP 错误和超时。
- 坐标转换成功与错误。
- 测试 API 的两步摘要和密钥不泄漏。
- 设置页面、导航、表单和前端操作存在。

真实验收：

1. Docker 自动迁移到 `0007`。
2. 将用户提供的 AK 通过本机 API 写入数据库，不进入提交差异。
3. 设置为启用，默认城市“广州”，关键词“三溪地铁站”。
4. 点击或调用测试接口，确认地点提示和坐标转换均成功。
5. 检查日志、API 响应和 Git 差异均不包含完整 AK。
6. 应用与数据库容器保持 healthy。

## 11. 后续扩展边界

后续新增其他 API 时：

- 继续复用 `integration_settings` 表。
- 为每个提供商建立固定客户端、校验模型和测试流程。
- 页面按提供商增加独立卡片。
- 不允许数据库配置任意请求 URL。

百度地图配置稳定后，下一阶段可把首页“手动坐标”升级为“地点关键词 → 百度候选 POI → GCJ-02 → 神州扫描”，但不与本次设置子系统捆绑实现。
