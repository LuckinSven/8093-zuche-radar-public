# 神州车型雷达：第一版设计

## 目标与边界

这是一个只供单人使用、无需鉴权的神州租车车型发现系统。首个重点城市是广州，但数据模型和扫描配置支持扩展至全国。

第一版解决的问题是：根据地点与租期，发现附近实际可租的车型，聚合不同网点的车源和基础价格，保存历史变化，并记录个人的体验偏好。

不在第一版范围内：登录或多用户、订单提交、最终结算价采集、外部消息推送、地图作为主搜索入口、自动补全第三方车型资料。

## 数据源与接口事实

当前验证成功的神州移动端选车请求为：

- 网关：`POST /api/gw.do?uri=/resource/carrctapi/order/chooseCar/v3`
- 请求格式：表单字段 `data`，值为 JSON 字符串。
- 广州神州内部城市 ID：`14`，不是行政区代码 `440100`。
- 必要条件：取还车城市、取还车时间、入口类型以及用户选择的经纬度。

接口的当前响应包含网点、车型、`modelId`、`modelName`、`dailyPrice`、`packagePrice`、`modelDesc`、可订状态和神州原生 `modelGroups`。网点距离是 `deptDistance`。`fuel`、`seat`、`vehicleAge` 当前没有作为稳定独立字段返回。

列表价格必须标记为基础日租/套餐日租，不等同于最终结算实付。

## 使用路径

1. 在发现页选择广州常用地点，或输入任意城市地点、地铁站或经纬度。
2. 选择时间快捷项或自定义日期；默认租期为取车日 09:00 至次日 09:00。
3. 发起立即扫描，系统保存扫描批次并返回以车型为中心的结果。
4. 按距离、价格、神州分类、可订状态、个人状态或变化事件筛选。
5. 在车型详情查看其网点分布和历史；填写个人状态或人工车型补充。

自动扫描是探针点级可选能力，默认关闭。手动扫描是第一版主入口。

## 时间快捷项

- 本周六一天：周六 09:00 至周日 09:00。
- 下周六一天：下周六 09:00 至周日 09:00。
- 本周末两天：周六 09:00 至周一 09:00。
- 自定义：日期自由选择，时间默认 09:00 且可修改。

所有结果、历史记录和变化事件都绑定完整的取还车条件，不跨条件混合价格。

## 页面范围

### 发现页

选择地点和时间，手动扫描，显示车型卡。卡片展示最近网点、距离、基础价格、神州分类、个人状态以及新出现或价格变化等标记。

### 车型详情页

展示车型出现过的网点、各地点距离和价格、历史时间线、个人状态与人工补充资料。

### 扫描历史页

查看扫描条件、成功或失败、网点数、车型数和变化事件，并可回看旧扫描结果。

### 管理页

管理城市、常用探针点、自动扫描开关和频率、原始响应保留规则，以及人工资料来源与可信等级。

## 筛选

优先复用神州响应的 `modelGroups`，并把每次扫描的分组归属作为历史事实保存。当前实测分组包括经济型、舒适型、SUV、6 至 9 座商务车、豪华型，以及可能为空的新能源车、个性车、皮卡、房车和彩蛋车。

系统补充筛选：距离、价格区间、可订或候补、车身类型与座位数、能源描述、个人状态、首次出现、近期价格下降、首次出现在更近网点，以及预设地点与当前临时扫描结果。

车身、座位和能源先从 `modelDesc` 解析，标为“神州描述解析”。人工资料不覆盖神州原始数据；每个补充字段独立保存值、来源、可信等级和最后核对时间。

## 数据模型

- 城市：名称、内部 ID、中心坐标、启用状态。
- 探针点：城市、名称、坐标、覆盖目的、自动扫描开关和频率。
- 扫描批次：触发方式、请求条件、开始结束时间、结果统计、状态和错误信息。
- 原始响应：关联扫描批次的压缩 JSON，保留 60 天。
- 网点：以神州 `deptId` 唯一，保存名称、地址、坐标与可变资料。
- 车型：以神州 `modelId` 唯一；同名不同 ID 不能合并。
- 可租快照：扫描批次、网点、车型、价格、可订状态、原始描述和当时神州分组。
- 个人状态：未租过、想租、已租、喜欢、不考虑，另有备注和实际租车日期。
- 人工补充：车型字段值、来源、可信等级与核对时间。
- 变化事件：首次出现、重新出现、消失、价格变化、首次在更近网点出现。

标准化历史长期保留；原始 JSON 到期清理。

## 技术结构

项目目录为 `/opt/apps/zuche-radar-8093`。采用单体 Python Web 服务和 PostgreSQL：

```text
神州网关 → 采集适配层 → 扫描任务层 → PostgreSQL
                                       ├─ 原始响应（60 天）
                                       ├─ 标准化快照与变化事件
                                       └─ 个人状态与人工补充
Web 页面与 JSON 接口 ← 查询服务 ← PostgreSQL
```

采集适配层负责请求构造、响应字段映射与接口版本变化隔离。手动和自动扫描共用扫描任务层。后续全国规模增加时，可以单独扩展工作进程，不重写页面或核心数据模型。

## 可靠性与验证

- 扫描失败保存错误与请求条件，不覆盖最近成功数据。
- 扫描请求使用有限、可观测的重试，避免持续向神州接口施压。
- 展示页只读取本地已保存数据，扫描过程不阻塞页面。
- 使用已验证的广州响应构造脱敏测试样本，覆盖：响应解析、车型去重、分组保存、变化识别、筛选、时间快捷项、60 天清理规则和失败记录。
- 上线验收执行一次真实的广州手动扫描，确认接口状态、网点数量、车型数量和持久化结果。

## 未来扩展

- 新城市和新探针点通过管理页配置。
- 自动扫描结果可转化为新车型、近距离可租和价格变化提醒。
- 第三方车型资料可作为有来源、有可信等级的人工或后续自动补充。
- 数据库与任务边界支持后续增加全国扫描工作进程。
