# 地图永久缓存与神州网点发现设计

## 1. 背景与目标

百度地图个人开发者的地点检索日额度较低，而本系统主要搜索广州地铁站、商场、常用地址等相对固定地点。系统应永久保存有效地点结果，只在首次查询或用户明确刷新时消耗百度额度。

神州租车最终以取还车网点承载库存和价格。现有 `chooseCar/v3` 会根据坐标、租期和库存返回候选网点，不能证明这些网点构成城市完整目录。本设计在当前系统上增加城市目录、可恢复的广州网点遍历和覆盖统计，持续积累以 `deptId` 唯一标识的网点地理数据库。

本项目继续优化现有 FastAPI、PostgreSQL 和 Docker 系统，不重写为桌面程序。参考 `zeratulers/shenzhou-zuche-scanner` 的开放城市枚举、单线程限速和重试思路，但不复制其代码或任何会话数据。该参考项目每个城市仅使用城市中心坐标调用一次选车接口，不能作为完整网点目录来源，且仓库未提供许可证。

## 2. 已确认决策

- 百度缓存使用 PostgreSQL，不引入 Redis 或文件缓存。
- 缓存永久保留，只保存最新有效结果，不保存历史版本。
- 地点检索与坐标转换分别缓存。
- 百度测试必须绕过缓存，真实验证 AK 和两个服务。
- 普通查询遇到百度失败时可以返回已有旧缓存；刷新失败不得覆盖旧缓存。
- 系统设置保留“地图缓存”；城市同步和网点发现页面只使用匿名开放接口。
- 历史上的 Cookie/session fallback 方案已废弃，不实施、不提供设置或 API；匿名接口失败即返回安全错误，不回退认证。
- 第一阶段以广州为重点，数据结构和任务模型支持以后扩展全国。
- 网点覆盖只报告已发现数量和覆盖过程，不宣称绝对完整。

## 3. 数据边界

系统保留三类相互关联但不混用的数据：

1. **百度地点缓存**：回答“用户输入的地点在哪里”，例如地铁站、商场和地址。
2. **神州网点目录**：回答“实际可以取还车的神州服务点在哪里”，以神州 `deptId` 唯一标识。
3. **扫描点**：用户选择的常用观察位置，可以引用百度地点或神州网点，也可以继续手工填写坐标。

百度地点不直接冒充神州网点；神州网点也不能替代用户对地铁站和普通地址的搜索。

## 4. 数据模型

### 4.1 地点检索缓存

新增 `map_search_cache`：

- `id`
- `provider`，当前固定为 `baidu_maps`
- `region` 与 `normalized_region`
- `keyword` 与 `normalized_keyword`
- `results_json`，只保存整理后的候选地点数组
- `first_fetched_at`
- `refreshed_at`
- `last_hit_at`
- `hit_count`

`provider + normalized_region + normalized_keyword` 建立唯一约束。标准化只处理首尾空白、连续空白和可安全统一的大小写，不对中文名称做可能改变含义的模糊合并。

每个候选地点保存百度 UID（如有）、名称、地址、省市区、行政区编码、BD-09 经纬度等可用字段，不保存完整原始响应。

### 4.2 坐标转换缓存

新增 `coordinate_cache`：

- `id`
- `provider`
- `source_crs` 与 `target_crs`
- 规范化后的源经纬度
- 目标经纬度
- `first_fetched_at`
- `refreshed_at`
- `last_hit_at`
- `hit_count`

当前固定支持 `BD-09 → GCJ-02`。坐标以足够精度的数值列保存并建立唯一约束，避免浮点字符串差异造成重复请求。

### 4.3 城市目录

扩展现有 `cities`：

- 保留神州城市 ID、名称和中心坐标。
- 增加神州城市代码、英文名、目录是否仍开放、首次/最后发现时间和目录同步时间。
- 现有 `enabled` 继续表示是否出现在人工扫描选择中；同步的新城市默认关闭，广州保持开启，避免一次把 471 个城市全部放入首页。

城市同步通过匿名 `cityList/v1` 完成。当前实测匿名请求返回 471 个开放城市，但系统不得把该数量写成常量。

### 4.4 神州网点

扩展现有 `departments`：

- 关联城市。
- 保留神州 `deptId`、名称、地址和经纬度。
- 增加行政区、营业时间、全天营业、自助取还等已确认可获得的字段。
- 增加 `first_seen_at`、`last_seen_at`、`last_synced_at`。
- 增加 `discovery_source`，区分选车接口、未来网点目录接口和人工补充。
- 增加 `active_state`，使用“已发现、近期出现、长期未见、人工停用”等可解释状态，不因一次未返回就删除网点。

以神州 `deptId` 唯一更新最新信息；刷新时覆盖可验证字段，不保留字段历史。人工补充继续使用已有来源和可信度机制，不覆盖神州原字段。

### 4.5 网点发现任务

新增 `department_discovery_runs` 和 `department_discovery_points`：

- 任务保存城市、状态、租期样本、限速设置、计划点数、完成点数、请求数、新增/更新网点数、开始/结束时间和安全错误摘要。
- 点位保存来源类型、经纬度、扫描轮次、最后扫描时间、返回网点数、新增网点数和重试状态。
- 唯一点位按城市和规范化坐标去重，任务中断后可以从未完成点继续。

## 5. 百度缓存流程

### 5.1 普通地点搜索

1. 标准化城市和关键词。
2. 命中 `map_search_cache` 时直接返回，并更新命中次数和最后使用时间。
3. 未命中时调用百度地点提示。
4. 只在百度业务成功且至少有一个有效地点时事务性写入缓存。
5. 坐标只有在需要用于神州扫描时才执行转换，并优先读取 `coordinate_cache`。
6. 响应明确标记 `source=cache` 或 `source=baidu`，同时提供缓存更新时间。

### 5.2 手动刷新

- 强制请求百度并绕过读取缓存。
- 成功后原子覆盖最新结果。
- 网络、额度、权限、空结果或格式异常时保留旧缓存并显示安全错误。
- 单条刷新不会清理相关坐标缓存；新坐标会形成新的坐标缓存条目。

### 5.3 API 测试

设置页“测试 API”始终直接调用百度地点提示和坐标转换，不读缓存。测试成功可以更新“最近验证时间”，但不以缓存命中冒充接口可用。

## 6. 神州网点发现流程

### 6.1 城市目录同步

匿名调用 `cityList/v1`，按神州城市 ID upsert。同步只更新城市目录，不自动启动全国选车扫描。

### 6.2 广州遍历

广州任务采用单并发、可恢复的渐进覆盖：

1. 从广州城市中心、现有扫描点、已有网点坐标和已缓存地铁站开始。
2. 在广州配置的覆盖范围内生成确定性网格点；网格生成不调用百度。
3. 每个点调用 `chooseCar/v3`，以 `deptId` 合并网点。
4. 新发现网点周边可以生成少量下一轮点位，补充行政区边缘和候选截断区域。
5. 连续一轮全部点位没有新增网点时结束当前任务；用户可以扩大范围、减小网格间距或换租期样本继续扫描。
6. 对不同未来日期保留可选租期样本，因为无库存网点可能不会出现在某一次选车响应中。

任务必须显示“已发现网点”，不能显示“广州全部网点”。即使返回 `deptTotalNum`，该值也只解释为当前坐标、时间和库存条件下的响应数量。

### 6.3 请求节制

- 默认并发数为 1。
- 请求之间使用不低于 2 秒的基础间隔和小幅随机抖动。
- 网络和 5xx 使用有限指数退避；业务拒绝、匿名接口失败和参数错误不盲目重试，统一返回安全错误。
- 支持用户停止和稍后继续。
- 每个任务设置最大请求数，达到上限后安全停止并保留进度。

### 6.4 网点目录接口

截图中的神州“网点列表”很可能使用独立目录接口。后续通过用户本人设备的网络请求信息或 H5 公开资源继续确认；在没有证据前不猜测接口、不高频探测。若找到目录接口，先以广州结果与遍历库交叉验证，再决定是否替代网格发现。

## 7. 历史决策：会话后备已废弃

本设计的早期版本曾计划在 `integration_settings` 保存 Cookie，并在匿名请求失败后进行一次 session fallback。该方案已废弃，不实施、不保留 API、设置页、数据读写或请求头注入。保留本节仅用于追溯设计变更。

当前及后续城市同步、普通选车和网点发现均只调用匿名开放接口。任何匿名接口失败都记录不含认证信息和个人信息的安全错误；不得猜测认证状态、重试认证或切换请求身份。

## 8. 页面与 API

### 8.1 设置导航

系统设置增加二级导航：

- 集成配置
- 地图缓存
- 神州网点

### 8.2 地图缓存页

展示地点缓存数、坐标缓存数、总命中次数、最近刷新时间；支持按城市和关键词筛选，展开查看候选地点和坐标，执行单条刷新、单条删除和二次确认后的全部清理。

### 8.3 神州网点页

展示匿名城市目录同步结果、广州已发现网点数量、含坐标数量、行政区分布、最后发现时间和最近任务状态；支持网点筛选、详情查看、同步城市目录、启动/停止/继续广州遍历，以及查看每轮新增趋势和覆盖点位统计。

页面必须明确区分“目录开放城市”“已发现网点”“当前有库存网点”。

### 8.5 固定 API

API 使用固定路由，不允许数据库配置任意外部 URL：

- 地点搜索、单条强制刷新、缓存列表/统计、单条删除和全部清理。
- 神州城市目录同步和列表。
- 网点列表、统计、发现任务创建、停止、继续和状态查询。

破坏性清理仅接受明确目标并由页面二次确认，不提供模糊的批量删除参数。

## 9. 错误处理与一致性

- 外部错误统一映射为不含 AK、认证信息、请求头和个人信息的中文消息。
- 缓存更新和网点 upsert 使用事务；一次刷新失败不留下半份新结果。
- 同一城市同时只允许一个活动网点发现任务。
- 容器重启后活动任务标记为中断，可由用户继续，不自动从头重跑。
- 缓存和目录接口的空结果不覆盖已有成功数据。

## 10. 测试与验收

所有新行为遵循测试先行：

- 仓储测试覆盖永久缓存、命中计数、覆盖最新结果和失败保留旧值。
- 服务测试覆盖缓存命中不调用百度、强制刷新调用百度、百度测试绕过缓存。
- 匿名接口测试覆盖城市目录解析、未知业务错误安全映射和任何响应不泄露认证信息。
- 城市同步测试覆盖 upsert、广州保持启用、新城市默认不出现在手动扫描下拉框。
- 网点发现测试覆盖 `deptId` 去重、任务恢复、单城市互斥、请求上限、连续无新增停止和不同租期样本。
- 页面测试覆盖三个二级入口、状态标记、刷新/清理确认和任务控制。
- 独立临时数据库从零迁移到最新版本。
- Docker 重建后检查健康、迁移版本、缓存持久化和任务恢复状态。
- 真实验收只执行低频、有限的广州请求，不打印密钥或原始敏感请求数据。

广州第一阶段验收指标：匿名城市目录同步成功；可启动、停止和继续网点发现；已发现网点按 `deptId` 唯一保存；页面能解释请求数、覆盖点数和新增趋势；不能以任何统计值宣称绝对完整。

## 11. 分阶段交付

### 阶段一：永久缓存与设置基础

- 地点/坐标缓存表、缓存服务与搜索 API。
- 地图缓存二级页面。
- 匿名城市目录同步。

### 阶段二：广州网点发现

- 网点字段扩展、发现任务与点位表。
- 广州渐进网格、限速、停止和继续。
- 神州网点二级页面与覆盖统计。

### 阶段三：目录接口与全国扩展

- 基于合法取得的请求证据确认神州网点目录接口。
- 使用目录接口交叉验证广州覆盖。
- 按用户选择的城市逐步扩展，不默认启动全国高频扫描。

## 12. 非目标

- 不引入 Redis。
- 不保存百度或神州每次响应的缓存历史版本。
- 不自动登录神州账号，不处理短信验证码。
- 不复制参考项目代码、认证信息、调试数据或账号信息。
- 不把“城市中心扫描一次”等同于完整网点列表。
- 不在第一阶段默认遍历全国 471 个城市。
- 不将 8093 端口或设置页面暴露到公网。
