# 神州车型雷达重做版设计规格

## 1. 目标与边界

本系统是供个人在局域网内使用的神州租车车型发现与历史追踪工具。第一使用中心为广州，但城市、扫描点和数据模型必须允许扩展到全国。系统以手动扫描为主要入口，也支持按扫描点配置独立的自动扫描开关和计划；自动扫描默认关闭。

系统不包含账号、鉴权、多租户、神州登录、下单或支付。页面显示的 `dailyPrice` 和 `packagePrice` 均标注为神州基础/列表价格，不得描述为最终结算价。

## 2. 交付形态

- 项目目录为 `/opt/apps/zuche-radar-8093`，服务端口固定为 `8093`。
- Docker Compose 启动 PostgreSQL 16 和应用容器；应用监听 `0.0.0.0:8093`，供局域网访问。
- PostgreSQL 使用命名数据卷持久化；应用启动时自动执行 Alembic 迁移。
- 容器提供健康检查，应用重启不丢失数据。
- 所有用户文档、页面文案和运维说明使用中文。

## 3. 系统架构

采用模块化单体：FastAPI 同时提供 JSON API 与服务端页面，扫描编排、神州网关、解析、持久化、变化检测、个人数据和调度各自拥有独立模块及接口。浏览器只调用本系统 API，不直接访问神州。

扫描任务当前在应用进程执行。扫描服务不得依赖网页层，使未来可将同一服务迁移到独立工作进程。所有手动和自动扫描必须经过同一条扫描链路。

## 4. 神州接口与地点处理

神州移动端网关为 `POST https://m.zuche.com/api/gw.do`。车型查询 URI 为 `/resource/carrctapi/order/chooseCar/v3`，城市定位 URI 为 `/action/carrctapi/order/cityLocation/v1`。请求使用表单字段 `data=<JSON 字符串>`，并发送移动端 User-Agent、Origin、Referer 和 X-Requested-With。

地点输入支持：

- 预设广州常用地点和地铁站；
- 输入地点名称并使用已保存坐标；
- 手动输入任意经纬度并临时扫描；
- 城市定位接口将坐标解析为神州内部城市 ID，例如广州为 `14`。

第一版不依赖地图操作。地图可作为未来增强，不得阻塞核心扫描流程。

## 5. 扫描流程

一次扫描包含地点名称、经纬度、神州城市 ID、取车时间、还车时间及触发来源。默认时间为所选日期 09:00 到次日 09:00，页面提供本周六一天、下周六一天、周末两天和自定义选项。

扫描流程：

1. 创建 `PENDING` 扫描记录并提交事务；
2. 调用神州网关，传输超时或 5xx 最多重试两次；
3. 校验响应状态并保存 gzip 压缩原始 JSON；
4. 按神州 ID 更新城市、网点和车型，写入不可变报价快照及原生车型组；
5. 与相同地点和租期的最近一次成功扫描比较；
6. 生成 `FIRST_SEEN`、`REAPPEARED`、`DISAPPEARED`、`PRICE_CHANGED`、`CLOSER_DEPARTMENT` 事件；
7. 标记扫描为 `SUCCESS`。任何失败标记为 `FAILED`，保留安全错误信息且不删除历史快照。

## 6. 数据模型与保留策略

核心实体为城市、扫描点、扫描任务、原始响应、网点、车型、报价快照、车型组成员、变化事件、个人车型状态和人工补充信息。

- 车型唯一身份为神州 `modelId`，不得按名称合并。
- 网点唯一身份为神州 `deptId`。
- 报价快照按扫描任务、网点和车型唯一，永久保存。
- 神州 `modelGroups` 作为来源事实按扫描保存。
- `modelDesc` 解析出的车身、座位和能源类型单独标注为“从描述推导”。
- 原始响应 gzip 压缩保存 60 天；每日维护任务删除严格早于 60 天截止时间的数据。
- 删除原始响应不得影响标准化扫描历史。

## 7. 车型发现与筛选

发现页以车型为中心聚合当前扫描结果，展示最低基础价、最近可租网点、距离、候选/可预订状态、神州原生车型组、描述推导属性、个人状态和变化标记。

筛选条件包括神州车型组、最低/最高价格、最大距离、可租状态、车身类型、座位数、能源类型、个人状态和变化类型；所有条件按交集应用。页面明确提示价格不是最终结算价。

## 8. 个人信息与可信补充

每个车型拥有一个当前个人状态：未租过、想租、已租、喜欢、不考虑。可保存备注和实际租用日期。

人工补充信息以不可变修订单独保存，字段包含字段名、内容、来源、可信度（低/中/高）和核验日期。人工信息不得覆盖神州来源字段，API 和页面始终分区展示两类信息。

## 9. 页面与 API

页面包括：

- `/`：地点与时间选择、立即扫描、完整筛选和车型卡片；
- `/models/{modelId}`：车型当前信息、网点报价、历史趋势、个人状态和人工补充；
- `/history`：扫描条件、状态、数量、错误和变化事件；
- `/admin`：城市与扫描点管理、自动扫描开关、计划配置、保留规则和系统状态。

JSON API 包括扫描创建/详情、发现查询、历史查询、城市与扫描点 CRUD、个人状态更新、人工补充新增/查询及健康检查。输入错误返回字段级 `422`，不存在资源返回 `404`，外部服务失败记录扫描后返回稳定的失败结果。

## 10. 调度与维护

调度器只装载 `enabled=true` 的扫描点，支持正数分钟间隔或合法 cron 表达式。配置变化后重建对应任务。启动时从数据库恢复任务，不创建任何默认启用的自动扫描。

每日维护任务按配置的固定 60 天规则清理原始响应。维护结果写入日志，不删除扫描、车型、报价快照或变化事件。

## 11. 测试与验收

- 使用录制并脱敏的广州成功响应测试请求格式、解析和持久化。
- PostgreSQL 集成测试验证 ID 唯一性、事务失败保护、历史比较、筛选、个人数据和 60 天清理。
- API 测试覆盖正常请求及 `422/404/失败扫描`。
- 页面测试覆盖四个页面、时间快捷选项和价格免责声明。
- 调度测试证明关闭扫描点不会创建任务。
- 全套自动测试、Alembic 升级和 Docker Compose 配置必须通过。
- 最终启动 Docker 容器并检查 `/healthz`、首页和数据库健康状态。
- 使用广州中心坐标执行一次真实扫描；外部接口若临时失败，系统本身必须保存失败记录并保持可用。
