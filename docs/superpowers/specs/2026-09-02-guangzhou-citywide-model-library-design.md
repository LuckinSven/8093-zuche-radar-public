# 广州全城车型扫描与永久车型库设计

## 1. 目标

系统以广州为中心，允许用户选择一个明确的取还车时间窗口，手动遍历广州当前全部神州网点，汇总该租期可租车型。用户先从车型角度浏览，再查看未来可以去哪些网点取车。

同时建立永久车型库：车型只新增、不删除。扫描更新车型的最近发现时间、来源标签和当前租期状态，但不会覆盖人工标签，也不会因为某次没有返回而删除车型。

本次保持现有 FastAPI、Jinja、原生 JavaScript、CSS 和 PostgreSQL 技术栈，不引入 Vue、React 或新的前端构建系统。

## 2. 已确认的产品规则

1. 全城扫描必须绑定一个明确租期，不混合不同日期和时间。
2. 扫描由用户手动触发，不增加自动定时扫描。
3. 广州当前约 91 个网点；标准全城扫描逐个使用网点坐标查询，完整性优先。
4. 任务支持进度、停止、继续和失败重试。
5. 永久车型库只增加、不删除。
6. “全城车型”和“车型库”是两个独立页面。
7. 全城车型页面一款车型显示一行，点击后展开各网点报价。
8. 价格只作展示，不作为首版筛选条件。
9. 距离统一为网点坐标到鱼珠地铁站服务点的直线距离，不使用神州每次查询返回的局部距离作横向比较，也不消耗百度地图额度。
10. 详细报价和神州原始响应保留 60 天；车型库和精简历史永久保存。

## 3. 对神州数据的解释

`chooseCar/v3` 返回的是指定租期和查询坐标附近“可以取到该车型的服务点”，不等同于车辆当前物理停放位置。同一车型、同一网点可能被相邻查询点重复返回。

系统保存的是“车型 + 租期 + 可取网点 + 报价”的可租关系，不将车型绑定为某个网点的固定库存。

同一车型在不同网点可能报价不同。系统先按车型和网点去重，再计算均价、最低价和最高价。价格均标记为神州基础/列表价格，最终以神州下单页为准。

## 4. 扫描任务

### 4.1 创建

首页提供以下配置：

- 城市固定默认为广州。
- 取车日期时间。
- 还车日期时间。
- 默认时间为 09:00 到次日 09:00。
- “启动全城扫描”按钮。

创建任务时固定一份网点目录快照。任务运行期间即使重新同步网点，也不改变该任务的计划点数量，保证进度可解释。

### 4.2 执行

- 每个网点坐标对应一个扫描点。
- 正式并发数默认为 3，并允许以后通过系统配置降低，但首版不在页面暴露并发参数。
- 每个扫描点最多重试 3 次，仅对超时、连接失败和上游 5xx 错误重试。
- 任务停止后不领取新点；正在执行的请求安全结束后保存结果。
- 继续任务时只处理未完成或可重试的点。
- 所有点成功后状态为“完整”。
- 存在最终失败点时状态为“部分完成”。
- 用户主动停止时状态为“已停止”。

任务执行期间不持有数据库事务等待网络请求。领取点、外呼和落库分别使用短事务，避免连接被长期占用。

### 4.3 去重

同一次任务内，详细报价唯一键为：

`任务 ID + 神州车型 ID + 神州网点 ID`

同一报价被多个查询点重复返回时：

1. 优先使用以该返回网点自身坐标发起的结果。
2. 若没有自身坐标结果，使用查询点到返回网点直线距离最短的结果。
3. 其他重复观察只保留在 60 天原始数据中，不重复参与均价计算。
4. 若重复观察价格不同，在原始数据中保留差异，精简结果使用上述优先级选出的报价。

## 5. 数据模型

### 5.1 全城扫描任务

新增全城扫描任务表，保存：

- 城市、取车时间、还车时间。
- 状态、计划网点数、成功数、失败数、请求数。
- 新发现车型数、可租车型数。
- 创建、开始、停止、完成时间。
- 安全错误摘要，不保存上游敏感错误正文。

新增扫描点表，保存每个网点的执行状态、尝试次数、领取令牌和最终结果计数。

### 5.2 永久车型库

复用现有车型表并补充：

- 首次发现时间。
- 最近发现时间。
- 最新神州车型名称。
- 最新能源类型及其来源。
- 最新图片地址和描述（上游明确返回时）。
- 最近一次完整扫描状态。

车型不会被扫描删除。人工标签继续使用现有个人状态和人工补充机制，扫描不得覆盖人工值。

### 5.3 详细报价

详细报价保存：

- 全城任务、车型、可取网点。
- 日均价、套餐价、可预订状态、库存类型。
- 上游描述和选中观察来源。
- 网点到鱼珠的直线距离。
- 首次和最后观察时间。

详细报价保留 60 天。

### 5.4 永久精简历史

每款车型在每次全城任务中保存一条永久汇总：

- 当前租期状态。
- 唯一可取网点数量。
- 均价、最低价、最高价。
- 距鱼珠最近距离和最近网点。
- 本次任务首次/最后观察时间。

均价只计算唯一可取网点中的有效报价；优先使用套餐价，没有套餐价时使用日均价。没有有效价格时均价为空，不使用 0 代替。

## 6. 可租状态

永久车型库针对选中的全城任务显示三种状态：

- **可租**：任务中至少一个网点返回该车型。
- **本租期未发现**：任务完整结束，所有计划网点均成功，但没有返回该车型。
- **扫描未完成**：任务尚未结束、被停止或有最终失败点，不能作否定判断。

“部分完成”任务中已经发现的车型仍可标记为可租，但未发现车型只能显示“扫描未完成”。

## 7. 页面结构

### 7.1 找车首页

首页只承担配置和任务状态：

- 选择租期。
- 启动全城扫描。
- 显示计划、成功、失败网点数量。
- 显示任务运行时间和安全错误摘要。
- 提供停止、继续、重试失败点。
- 完成后进入“全城车型”。

首页不展示大批车型卡片。

### 7.2 全城车型

只展示选中租期的聚合结果，一款车型一行。默认列为：

- 车型名称和首次/最近发现。
- 能源类型。
- 唯一可取网点数量。
- 距鱼珠最近直线距离。
- 网点均价。
- 价格区间或“所有网点同价”。
- 个人标签。

存在价格差异时显示“有价差”。点击车型后按需请求并展开各网点的实际报价，按距鱼珠距离排序。详情至少显示网点、直线距离和报价。

首版筛选项只包括：

- 可取网点。
- 距鱼珠距离。
- 当前租期状态。
- 首次发现、最近发现。
- 能源类型。
- 想租、喜欢、租过、不考虑等个人标签。

价格不作为首版筛选项。

### 7.3 车型库

展示所有曾发现车型，包括当前租期未发现的车型。默认显示最近发现时间倒序，并支持与全城车型相同的永久属性筛选。

车型详情显示：

- 首次发现和最近发现。
- 当前租期状态。
- 历次精简历史。
- 人工标签和人工补充。
- 当前租期可取网点报价。

### 7.4 报价明细

现有 `/data` 能力保留，作为“全城车型”的二级高级明细页，不再占主导航的核心位置。CSV 导出继续保留。

## 8. 接口设计

新增或调整以下系统接口：

- `POST /api/citywide-scans`：创建手动全城扫描。
- `GET /api/citywide-scans`：列出全城扫描任务。
- `GET /api/citywide-scans/{id}`：读取任务和进度。
- `POST /api/citywide-scans/{id}/stop`：停止任务。
- `POST /api/citywide-scans/{id}/resume`：继续任务。
- `POST /api/citywide-scans/{id}/retry-failed`：重试最终失败点。
- `GET /api/citywide-models`：数据库聚合、筛选和分页读取指定任务的车型。
- `GET /api/citywide-models/{model_id}/offers`：按需读取指定车型的网点报价。
- `GET /api/model-library`：分页读取永久车型库。
- `GET /api/model-library/{model_id}`：读取车型档案和精简历史。

写接口使用严格请求模型，拒绝多余字段。错误信息使用中文，隐藏数据库连接、上游地址细节和响应正文。

## 9. 性能方案

不更换前端框架，重点修改数据流：

1. 聚合、筛选、排序和分页在 PostgreSQL 中完成，不再读取整批报价后在 Python 中分页。
2. 全城车型列表每页默认 50 款，只返回当前页字段。
3. 网点报价在展开车型时按需加载，不随列表一次返回。
4. 前端筛选只替换结果区域，保留租期、筛选和展开状态。
5. 新请求发起时取消已过期的筛选请求，避免旧响应覆盖新结果。
6. 扫描进度只更新进度区域，不重复绘制车型表。
7. 数据页面取消固定 1480px 宽表格和页面内双滚动。
8. JavaScript 和 CSS 按核心页面拆分，公共代码保持小型、无构建步骤。
9. 不在全城车型和车型库页面使用 3 秒整页轮询；仅运行中的任务使用轻量进度轮询，页面不可见时停止。

## 10. 视觉方案

保持现有品牌风格，调整为清新、低干扰的配色：

- 页面背景使用浅米白到极浅灰绿的静态渐变。
- 顶部导航、筛选栏和扫描状态允许轻度半透明与磨砂。
- 车型数据行使用接近不透明的浅色底，保证阅读和滚动性能。
- 强调色继续使用低饱和青绿，价格使用克制的暖橙色。
- 边框细、阴影浅，不使用大面积深色卡片。
- 展开、筛选和状态变化使用约 180 毫秒的透明度或位移动画。
- 不动画模糊半径，不使用流动背景和持续动画。
- `prefers-reduced-motion` 下关闭非必要过渡。
- 不支持 `backdrop-filter` 时自动使用浅色实底。
- 手机端改为紧凑三列视图，隐藏次要字段，不使用缩小字号维持桌面表格。

## 11. 数据保留

- 永久：车型库、人工标签、车型首次/最近发现、每次任务的精简汇总。
- 60 天：详细网点报价、重复观察和神州原始响应。
- 清理任务只删除超过 60 天的明细和原始数据，不删除车型、人工数据和精简历史。
- 清理采用数据库分批删除，避免长事务影响页面查询。

## 12. 异常与可信性

- 上游单点失败不会删除既有车型或网点。
- 任务不完整时不能把未返回车型标记为“本租期未发现”。
- 能源类型优先使用神州原始信息，其次使用可靠解析，人工修正优先级最高。
- 上游本次缺少某标签时不清空已有可信标签。
- 全城扫描和车型页面不需要登录、Cookie 或用户鉴权。
- 所有价格提示“非最终结算价”。

## 13. 测试与验收

### 13.1 自动化测试

- 扫描任务状态机、停止、继续、重试和并发领取。
- 扫描期间数据库会话不跨网络等待。
- 91 个网点快照固定、重复报价正确去重。
- 自身网点观察优先于附近查询点观察。
- 均价、价格区间、最近距离和三态可租状态。
- 车型只新增不删除，人工标签不被覆盖。
- 完整任务和部分任务的否定状态不同。
- 60 天明细清理不删除永久汇总。
- 数据库侧分页、筛选和排序。
- 中文错误和敏感错误隐藏。
- 页面路由、筛选参数、按需报价接口和响应式结构。

### 13.2 部署验收

- Docker 构建成功，应用和 PostgreSQL 健康。
- 使用广州当前网点目录完成一次真实全城扫描。
- 任务显示计划、成功、失败和请求数量。
- 同一车型只显示一行，网点报价展开后数量与去重结果一致。
- 比亚迪海狮05等已知车型可以通过车型名称找到，并展示可取网点、均价、价差和距鱼珠距离。
- 桌面端不出现页面内双滚动；手机端不需要横向拖动主车型列表。
- 局域网访问和现有设置、网点、API 台账页面继续可用。

## 14. 实施顺序

1. 数据库模型、迁移、任务状态机和全城扫描服务。
2. 聚合查询、永久车型库、数据保留和系统 API。
3. 找车首页、全城车型、车型库和车型详情。
4. 报价明细衔接、配色、动画、响应式和性能优化。
5. 完整回归、真实全城扫描、Docker 部署和 GitHub 推送。

每个阶段都保持现有手动鱼珠扫描和设置页面可用，不以未完成的新页面替换现有功能。

## 15. 不在本次范围

- Vue、React 或其他前端框架重写。
- Cookie、登录账号和认证处理。
- 自动定时全城扫描或消息推送。
- 百度驾车距离批量计算。
- 猜测神州未明确返回的车辆配置。
- 下单、支付或调用需登录的神州接口。
